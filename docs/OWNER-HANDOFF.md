## Take control of the source

1. Sign in as the repository owner and verify MFA, recovery access and notification settings privately.
2. Clone the public repository for future work; **do not add the private development history as a remote or merge source**. Enable the documented local hooks.
3. Review open dependency-update pull requests before merging. No dependency PR is automatically approved or merged.
4. Use branches and pull requests; retain the required `verify` check and the no-force-push/no-deletion safeguards on `main`.
5. Read [Self-hosting](SELF-HOSTING.md) for local evaluation and [Operations](OPERATIONS.md) for the production acceptance/runbook. Public source availability does not authorize production data entry.

## Stop conditions

Pause customer enrollment if cross-tenant access occurs, backups cannot be restored, monetary reservations are bypassed, terms/identity/payment entitlements disagree, or projected gross margin falls below the safety threshold. Pause the affected provider if retention/price/account terms change without review.

## Definition of launch

Launch is not a public README or a passing build. It is the same reviewed artifact operating behind TLS with provisioned identity, payment entitlements, KMS, backups, monitoring, support/legal notices, bounded provider spend and an observed end-to-end customer journey. The source release can precede that hosted launch and should be described honestly as the local foundation.
