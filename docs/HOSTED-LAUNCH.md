# Hosted Launch Workstream

Updated October 14, 2026. This is WHOAYO, formerly developed under the Origin Studio name. No other application's accounts, billing, credentials or deployment are reusable by implication.

## Product And Commercial Direction

Origin Studio preserves the starting point and documents what happened next. The user records a private idea, obtains the selected independent timestamp, works with configured AI models and skills, and preserves subsequent changes. The requested paid service adds an enrollment fee plus a recurring usage plan. Prices, included model tokens/build minutes/storage, reset periods, overage policy, refunds and taxes are not approved. Do not take payment or promise unlimited access. The first invited group's free/paid policy is awaiting the owner.

Allocate hosting, managed identity, storage/backup, model spend and sandbox compute within a newly approved itemized budget before provisioning. Planning allowances are not authorization to create resources. AWS budget notifications alone are not a hard cap and do not cover other providers' bills.

The proposed post-gate tier and margin model is in [Commercial plan](COMMERCIAL-PLAN.md). The required Checkout/webhook/entitlement state machine is specified in [Payments and entitlements](PAYMENTS.md). Neither document activates an offer or payment path.

Keep the public-domain parameter unset until an owned name is selected and verified. A suggested name is not proof of ownership or authorization to buy it.

## Current Local Implementation

- Exact package-to-proof linkage for the Origin Studio concept was checked read-only. Public metadata in `src/concept-evidence.json` contains no private concept, nonce, account ID or path. `scripts/check-concept-link.mjs` reproducibly checks the package, payload, completed proof and historical completion report against it. This does not repeat a live explorer check or claim local-node validation. An operator inspected the covered concept, not just its title.
- Public copy now says we used Origin Studio to preserve its own concept. It distinguishes code drafting from execution/publishing and labels planned connections and paid membership honestly. The requested slow swirl/twinkle is deferred.
- `server/managed-identity.mjs` implements a default-off Cognito authorization-code/PKCE adapter using pinned `openid-client`, with signature/issuer/audience/nonce checks, verified-email requirements, one-use browser-bound transactions, expiry, bounded pending requests and network responses, timeout signals, fixed endpoints and sanitized failures. It returns identity claims without provider tokens.
- `infra/identity.cfn.json` prepares a dedicated retained Cognito pool, code-only client and managed-login domain/branding. It requires authenticator MFA, offers verified-email recovery, and limits creation to invitations. There is no chosen public-domain default. The JSON and security invariants are tested locally; it is not validated by CloudFormation, provisioned, or live-tested.
- `server/http.mjs` now wires default-off `/api/identity/start` and `/api/identity/callback` routes, exact hosted-origin checks, pre-authentication CSRF, one-use HttpOnly callback cookies, Secure application cookies in hosted mode, fixed redirects, provider logout and managed-session revocation. Public self-registration closes while managed identity is enabled; existing local sign-in remains separate.
- `managed_identities` maps the verified provider `(issuer, subject)` digest to a new app-owned user ID. Provider claims are encrypted, restored with the vault and never linked to an existing account by email or display name. Backup schema validation and restore tests include this mapping.
- A single offline synthetic pilot test now covers two application sessions, idea preservation, a cryptographically verified synthetic signed timestamp, exact AI disclosure approval, one synthetic model response, attributed artifact saving, evidence verification/export and global session revocation. It makes no real identity, timestamp or model request.
- Default-off test billing adds account-bound Checkout/portal, signed raw webhooks, durable event deduplication, current-subscription reconciliation and managed-account entitlement checks before model spending. Monetary reservations use the selected plan's provider-cost allowance. This is synthetic-tested only; live payments are explicitly rejected.

**Important:** these are locally and synthetically tested application controls, not live hosted acceptance. No Cognito pool, public origin, certificate, DNS, ingress, email, invitation or production database was created or changed. Real recovery, MFA, disabled-user behavior and cross-device access remain unverified. Do not tunnel the development server as a substitute for the remaining hosting work.

## Next Vertical Slice: Provisioned Invited Pilot

1. Confirm an owned public origin, dedicated AWS account/region and itemized provisioning estimate. Obtain the resource/IAM and deployment approval for that exact target. Do not infer account access or reuse credentials from unrelated projects.
2. Validate and provision the retained invited-only identity template, then place the existing exact-origin HTTP mode behind reviewed TLS ingress. Keep the application process loopback-bound; do not treat a public tunnel as protected ingress.
3. Persist login transactions in a TTL-bound shared encrypted store before multi-instance hosting. The current bounded in-memory transactions deliberately expire on restart and cannot cross instances. Add infrastructure rate limits and sanitized operational logs without recording callback codes or tokens.
4. Exercise the real invited-user lifecycle: mailbox ownership verification, temporary-password change, authenticator enrollment, login on two devices, forgotten password, expired/replayed recovery code, lost-MFA process, provider logout, application-session revocation, disabled-user denial and cross-tenant denial. An invitation or administrator-entered email is not verified-mailbox evidence. Do not administratively set `email_verified` merely to satisfy the adapter.
5. Add a verified recovery/session-revocation integration. A hosted password reset must invalidate appropriate application sessions and outstanding approvals; Cognito token revocation alone is not a complete application-session strategy. Email recovery must not bypass the second factor.
6. Move production key custody to a dedicated KMS policy, establish scheduled off-device encrypted backups, and complete a timed restore into a fresh environment before accepting confidential pilot data.
7. Invite one synthetic hosted user and repeat the locally tested preserve/timestamp/model/save/export journey through the deployed origin. Only after that succeeds should a small human design-partner cohort receive invitations.
